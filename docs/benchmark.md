# A / B 对比

A 是 `oui.mbt patch` 之后的 `@openuidev/lang-core@1.0.1`。B 是同一个包、patch 之前。patch 只替换语句解析。分类、Schema 物化和 Renderer 仍是官方代码。

```bash
npm ci --prefix web
pnpm run benchmark
```

`--skip-demo` 只跑体积和 Node 解析，不打包 demo、也不开浏览器。结果写到 `.bench/report.json`。

## 测什么

| 项 | 做法 |
| --- | --- |
| lang-core 体积 | 官方 `dist/index.mjs` 与 patch 后的同一文件，再加上 A 必须带着的 `npm/index.js` 和 `npm/parser.wasm.js`。各报原始、gzip、brotli。 |
| 解析耗时 | 同一份 Schema、同一份 OpenUI 源。样例是 `web/signup.openui`、50 个字段、400 个字段。各报 `createParser().parse`、复用 parser 的 `parse`，以及按行 `push` 的中位数和 p95。冷启动另计：新进程里 import 模块的时间，A 含 Wasm 编译。 |
| 页面耗时 | 同一份 `web/src/bench.jsx` 打两次生产包。一次装 B 的 dist，一次装 A 的 dist。Headless Chrome 打开本地页面，从导航开始计到 Renderer 提交注册表单后的下一帧。每个包 7 次，第 1 次是冷加载。 |
| demo 体积 | 上面两次生产包里 html、js、css 的原始字节和逐文件 gzip 之和。source map 不计入。 |

400 个字段不做流式计时。流式实现会按块重解析整段缓冲，行数上去之后耗时主要来自重解析次数，不再反映单次解析。

## 不测什么

整库 `pnpm test` 的墙钟时间不作为性能结果。官方仓库里大量包不会加载 parser，Vitest 启动本身就占掉大部分时间，一次跑完的抖动也盖过解析差异。兼容性流水线已经用这套测试看正确性。

不维护两份 demo 源码。两份源码很快会分叉，体积和耗时就不再只差 parser。

页面计时不是解析耗时。Renderer、React 和组件库两边相同。这份注册表单的解析差在 0.1 毫秒以内，页面时间里看不出来。A 多出来的页面字节是 Wasm。

## 一次本机结果

2026-10-16，本机重新运行会覆盖 `.bench/report.json`。下面是该次结果。A、B 的结构指纹一致：注册表单 8 条语句、0 个错误，50 个字段 51 条语句，400 个字段 401 条语句。

### 体积

`dist/index.mjs` 本身几乎一样。A 多出来的是 Wasm 运行时。

| 文件 | 原始 | gzip |
| --- | ---: | ---: |
| B `dist/index.mjs` | 180172 | 48901 |
| A `dist/index.mjs` | 180649 | 49113 |
| A `parser.wasm.js` | 83784 | 34758 |
| 其中的 Wasm 二进制 | 62770 | 26077 |

demo 生产包（html + js + css，逐文件 gzip 后相加）：

| | 原始 | gzip 之和 |
| --- | ---: | ---: |
| B | 3713817 | 1336967 |
| A | 3791708 | 1371165 |
| A − B | +77891 | +34198 |

入口 `bench.*.js` 从 31609 字节（gzip 17969）变成 115859 字节（gzip 53786）。共享的大包略小，因为语句解析改成了对外调用。

### 解析

复用 parser 的 `parse` 中位数，单位毫秒。`createParser().parse` 在短文档上主要耗在官方的 parser 创建，不单列。

| 文档 | B | A |
| --- | ---: | ---: |
| 注册表单，516 字节 | 0.0315 | 0.0918 |
| 50 个字段 | 0.1070 | 0.2443 |
| 400 个字段，22085 字节 | 0.7696 | 1.8576 |

按行推送的中位数：注册表单 B 0.1545、A 0.4352；50 个字段 B 2.1976、A 4.7470。新进程 import 的中位数 B 35.4 毫秒、A 33.7 毫秒，Wasm 编译含在 A 里。

### 页面

Headless Chrome，从导航到注册表单画出后的下一帧。每个包 7 次，第 1 次是冷加载。

| | 冷加载 | 后 6 次 |
| --- | ---: | --- |
| B | 373.9 | 167.5、170.2、160.0、166.2、176.7、166.4 |
| A | 268.9 | 178.6、166.8、169.9、169.0、172.5、176.9 |

冷加载各只有一次，不能用来排名。后 6 次都在 160–180 毫秒。
