# @heyq02/openui.mbt

MoonBit parser for [OpenUI Lang](https://github.com/thesysdev/openui), compiled to Wasm-GC.

`parseProgram` returns JSON whose expression nodes use the same `k` discriminant as `@openuidev/lang-core`. Loading the module instantiates the Wasm module synchronously.

```js
import { parseProgram } from "@heyq02/openui.mbt/parser";

const program = parseProgram('root = TextContent("Hello", "large")');
```

`materializeProgram(source, schema, rootName)` returns the element tree plus `errors`, `unresolved`, `orphaned`, and `incomplete`.

`createStream(schema, rootName)` keeps a buffer in Wasm. Closed lines stay parsed. `push` and `set` take an optional `complete` flag and return the official `ParseResult`. An unfinished line is auto-closed for that result and is not committed until it closes. `dispose` drops that session.

`parseMessage(raw, options)` splits an OpenUI `]]>openui:` message. `options.streaming` holds a partial marker. The result is `{ content, context, attributes, end }`. `buildMessage(message)` writes that message back.

```bash
npm install @heyq02/openui.mbt @openuidev/lang-core
npx oui.mbt patch
```

`oui.mbt patch` rewrites the installed `@openuidev/lang-core`. `createParser().parse` and `createStreamingParser()` preprocess, auto-close, materialize, and extract state, query, and mutation statements in Wasm. They return the official `ParseResult` shape. `parseMessage()` and `buildMessage()` split and write `]]>openui:` messages in Wasm. `parseRules()`, `parseStructuredRules()`, `enrichErrors()`, `mergeStatements()`, `jsonToOpenUI()`, `evaluate()`, and the built-in field checks also run in Wasm. `evaluate()` decides which side of `&&`, `||`, and `?:` runs. `Count`, `First`, `Last`, `Sum`, `Avg`, `Min`, `Max`, `Abs`, `Floor`, `Ceil`, and `Round` run in Wasm. `Run`, `Set`, and `Reset` decide in Wasm, and the host rebuilds each step from the original nodes. `generatePrompt()` assembles its text in Wasm. `generateCloudConfig()` checks the library in Wasm, and the host still serializes the config block. `generateSystemPrompt()` chooses its branch in Wasm and still records telemetry in the official JavaScript. `isElementNode()`, `isReactiveAssign()`, and `isRuntimeExpr()` also run in Wasm. `isActionPlan()` and `flattenPlans()` classify in Wasm, and the host copies the original steps before `ownSteps()`. `extractToolResult()` chooses the content in Wasm, and the host still returns `structuredContent` and parses text. `stableStringify()` and `buildCacheKey()` build query cache keys in Wasm. The host still calls `toJSON` and reports cycles. `resolveField()` splits paths in Wasm, and `toNumber()` converts strings and booleans in Wasm. Numbers stay on the host so `-0` and `NaN` keep their values. `evaluateRoot()` chooses its branch in Wasm, and a matching element still goes through `evaluateElementProps()`. `Each` checks its arity, array, and loop variable in Wasm, and the host still evaluates the template. `evaluateElementProps()` chooses each prop step in Wasm and builds the runtime error text there. The host still recurses, evaluates, and reads state. `createStore()` decides equality and initialization writes in Wasm. Stored values and listeners stay on the host. `createQueryManager()` chooses the snapshot value and the loading, refetching, and error lists in Wasm, and builds query and mutation error text there. Cache entries, timers, and `callTool` stay on the host. `resolveStateField()` and `stripReactiveAssign()` choose their branch in Wasm. The host still reads state, calls `evaluate()`, and keeps the original `setValue`. For function and action arguments, Wasm decides whether an explicit `null` on an optional parameter is omitted and whether a required parameter is missing its default. The host still evaluates the arguments and reads `default`. `Sort` and `Filter` choose in Wasm: a non-array result, numeric order or `localeCompare`, and the filter operator. `localeCompare` and `==` stay on the host. `evaluateElementInline()` and `evaluateElementProps()` ask Wasm whether `hasDynamicProps === false`. A frozen element is returned as itself. Otherwise the host still evaluates each prop. `validate()` chooses the empty, required, email, URL, number, length, and pattern branches in Wasm. The host still creates `URL` and `RegExp`. `callFunction()` chooses a missing argument, an invalid argument, a thrown error, and return checking in Wasm. The host still calls the function, schema `checkValue()`, and `reportError`. A custom action chooses a missing argument and an invalid value in Wasm. The host still records the step in the original `WeakSet`. `mappedProps` chooses a state ref, a reactive assignment, and a child element in Wasm. The host still reads state, calls `evaluate()`, and keeps the element object. `getScalarTypeInfo()`, `checkTypeMismatch()`, and `jsType()` choose the enum, const, scalar type, and array branches in Wasm. The host still reads schema fields and joins enum text with the original `JSON.stringify`. `validationMessage()` chooses the type, missing-field, unknown-component, excess-argument, and root messages in Wasm. The host still reads `issue` fields in the official order and joins the original sentences. `validateSchemaValue()`, `validateObjectValue()`, `validateArrayValue()`, and `validateLeafValue()` choose the object, array, and leaf branches in Wasm. The host still keeps the original value and copies it when a default or a type mismatch changes it. `checkValue()` chooses a strict failure in Wasm. `evaluateArgs()` chooses named arguments in Wasm. `pushValidationIssue()` chooses the warning severity in Wasm. The host still reads `reportError`, `mappedProps`, and `issue.code` in the official order. `getSchemaDefaultValue()` chooses whether a default applies in Wasm. `isCompositeSchema()` chooses the composite keys in Wasm. `refName()` chooses a ref name in Wasm. `buildParamsSignature()` chooses the parameter signature in Wasm. The host still reads `default`, `$ref`, and `in` in the official order. `evaluatePropCore()` chooses an action plan in Wasm. `evaluateActionCall()` chooses the Action argument in Wasm. `isStep()` chooses a built-in step in Wasm. The host still reads `node.name`, `args`, and `BUILTIN_CALLS` in the official order. `tokenize()` lexes in Wasm and returns the official numeric `t`, with string values restored by `JSON.parse`. `parseExpression()` builds the expression in Wasm from numeric tokens and copies each leaf `v` from the original token. `OpenUrl` and `ToAssistant` build their steps in Wasm, and `context` stays the host value. `substituteRef()` replaces `Each` loop refs in Wasm, and `Each` still evaluates the template on the host. Value operations stay on the host so `==` and object identity keep their official behavior. `Action` still evaluates its arguments on the host. `walkAST()`, `isASTNode()`, `toLiteralAST()`, and `literalValue()` also run in Wasm. `walkAST()` still hands the live node to the visitor. `url` and `pattern` still use the host `URL` and `RegExp`. The Renderer stays in OpenUI. The patch matches lang-core 1.0.1. A different version, or a 1.0.1 bundle whose parser call sites have changed, makes the command exit before it writes either file.
